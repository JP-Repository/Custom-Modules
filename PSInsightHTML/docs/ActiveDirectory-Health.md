# Active Directory Health assessment (11.15)

This provider-owned assessment interprets the normalized snapshot and `ActiveDirectory.HealthEvidence` from 11.14. It performs **no collection**. Inventory remains factual and neutral; Windows Server 2022/2025 Readiness remains a separate assessment. The application report is generated by `Examples/ActiveDirectory/Health/Invoke-PSIADHealth.ps1` under `Reports/Health/`.

## Rule and outcome contract

`Providers/ActiveDirectory/Rules/Health/HealthRules.psd1` is the offline, versioned rule pack. Each normalized rule exposes Id, Title, Category, Description, Applicability, EvidenceRequirements, Evaluation, Outcome, Severity, Weight, RequiredForDC, Recommendation, Validation, Source, Version and Tags. Every source is labelled **provider-defined operational threshold**; no vendor or compliance endorsement is implied. `Thresholds.psd1` holds numeric defaults. `Test-PSIADHealth -ThresholdOverrides @{ ... }` accepts known positive numeric keys and validates threshold ordering. Review thresholds against local operating policy before use.

Outcomes map directly into the existing assessment vocabulary: Healthy → Ready, Review → Review, Critical → Blocked, unavailable → NotTested, irrelevant → NotApplicable. The generic assessment engine calculates weighted score and category posture. The Health display verdict maps generic Ready → Healthy, ReadyWithReview/ReviewRequired → Review, NotReady → Critical, and Incomplete/Unknown → Incomplete. Any Blocked check or open critical finding overrides a high score. Coverage is the collector's separate percentage; it is never a Health score.

Collected facts are evaluated only if the minimum required fields exist. Partial evidence is NotTested unless a future rule explicitly defines sufficient partial facts. Failed, NotSupported, NotRequested and NotTested remain NotTested. No unavailable measurement becomes Healthy. NotApplicable is used only for explicit role/scope exclusions, such as DNS Server checks on a non-DNS DC or writable SYSVOL/DFSR checks on a read-only DC. A successful empty result is distinct from a failed query. Exceptions use the existing PSI exception contract; they record approved decisions but do not silently erase observed findings or change score.

## Initial rule matrix

| Category | Rule IDs | Evidence and interpretation |
| --- | --- | --- |
| Directory Services | `ad-role`, `reachability`, `ntds`, `netlogon`, `kdc` | Observed role and remote reachability; essential stopped services block. One service does not establish whole-directory Health. |
| Replication | `replication` | Both partner and failure queries must complete. No current failures and recent success is Ready. Any current/consecutive failure is Review; ≥3 consecutive failures or >180 minutes since last success is Blocked. External evidence-only partner identity is retained without treating it as an assessed DC. |
| SYSVOL / DFSR | `sysvol-share`, `netlogon-share`, `dfsr-service`, `dfsr-migration`, `dfsr-folder` | Missing required shares block on writable DCs. DFSR service and migration are distinct. Replicated-folder state is explicitly NotTested because the current contract has no reliable measurement; share presence never proves folder Health. |
| DNS | `dns-service`, `dns-client`, `dns-zones`, `dns-forwarders`, `resolver-reachability`, `forwarder-reachability` | DNS service and server-side queries are role-aware. No configured client resolver is Review. A failed explicit probe is Review. Unavailable DNS tooling is NotTested. Empty forwarder list is not by itself a failure; forwarding design is an organizational choice. |
| Time | `time-source`, `pdc-source`, `w32time-service`, `time-reachability`, `time-offset` | Source observation, PDC configuration, service, independent reachability and measured offset are separate. Local CMOS source is Review. Offset requires an actual measurement; default review boundary is 100 ms. A source string alone never completes Time Health. |
| Capacity | `disk`, `memory`, `cpu`, `uptime` | System drive free <10 GB blocks; 10–<15 GB is Review. Memory ≥90% and CPU ≥85% are Review from one sample only. Uptime ≥180 days is Review context, never Critical. |
| Topology | `site`, `unmapped-subnets`, `site-links` | Missing site and observed unmapped subnets are Review. An empty completed site-link query is not a failure; site-link design is not inferred. |
| Events | `events` | Only Error/Critical observations in selected operational categories within a completed bounded query are Review. Informational events are ignored. Incomplete/failed event queries yield NotTested, never a clean-event conclusion. The rule covers only queried logs and categories; there is no unverified vendor event-ID claim. |
| Backup | `backup` | Only explicit medium/high or fictional sample provider input is evaluated. ≤1 day Ready, >1 to ≤3 days Review, >3 days Blocked. No provider input is NotTested, not “no backup.” |
| Connectivity | `ports` | Tested failed ports are Review with source and destination retained. NotTested ports are not asserted reachable or failed. |
| Services | `pending-reboot` | Explicit reliable observation is Review when pending. Live profiles lacking a common reliable query remain NotTested. |

All operational thresholds and score boundaries are in `Thresholds.psd1`. The event rule intentionally matches reviewed severity/category fields in current evidence rather than asserting undocumented event IDs. Every finding links to the affected resource, observed and expected states, source observation IDs, a non-destructive next action, and validation guidance. The application exposes overview, category views, checks, findings, resources, evidence, coverage, topology/tree and optional exceptions through existing PSI components. Search, filtering, print projection, and Light/Dark/Auto use the shared engine.

## DC and relationship presentation

Per-DC display state uses this precedence over checks: any Blocked → Critical; else any Review → Warning; else any **required** NotTested → NotChecked; else at least one required Ready → Healthy; otherwise Unknown. `dfsr-folder` is explicitly optional for the per-DC display because folder-state evidence is not collected; it still appears as NotTested in the assessment, score, findings and detail. This prevents an absent optional telemetry feed from hiding a DC whose required observed checks are healthy. It does not claim complete DFSR folder Health.

Topology nodes use the existing server icon and generic resource detail. Site, domain, OS, GC, FSMO/PDC, CPU, memory, disk, uptime, time source, finding counts, per-category Health and evidence links appear where available. Replication edge status comes from the same Health observations as the rule: Healthy, Warning, Critical, or Unknown when partner/failure query evidence is incomplete. Edge detail retains naming context, last success, consecutive failures and error. Evidence-only external partners stay neutral. Existing node type/status/relationship filters and the Site detail filter allow focus; the 100-node graph safety limit and mobile relationship list remain in force. A site context table aggregates DC counts without inventing a site score. Semantic surfaces and distinct shapes use centralized Light/Dark tokens; Inventory resources remain neutral.

## Fictional scenario and limits

The example uses the existing eight-controller fictional snapshot. `Add-PSIADHealthFictionalObservations` adds clearly labelled fictional measurements for one fully observed controller and a failing replication link. It **does not** change the shared snapshot or readiness inputs. The displayed collection-coverage percentage remains the original snapshot collector coverage; it does not count these extra fictional scenario facts. The sample includes Healthy, Warning, Critical, NotChecked and NotApplicable outcomes. Mocked-live input uses the existing command adapter without contacting AD.

Known evidence gaps remain visible: live DFSR replicated-folder/migration state, independent resolver and NTP probes, measured live time offset, broad reliable pending-reboot discovery, automatic backup discovery, and complete event categories. The fictional example is not a production Health conclusion. Print/PDF projects the assessment model and selected report tables; validate in a browser before circulation.
